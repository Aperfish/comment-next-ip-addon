# 发布前检查

## GitHub

- [ ] 创建 Aperfish/comment-next-ip-addon 仓库，启用 Issues，核实主页和源码地址均可访问。
- [ ] 上传仓库内容，不上传 work、.cache、个人密钥、原版输入 JAR。
- [ ] 检查 GPL-3.0 LICENSE、NOTICE、第三方许可及源码来源。
- [ ] 按 BUILD.md 在干净目录构建。
- [ ] 完成下列实机验证后再考虑稳定发布。
- [ ] 创建 v1.0.13-4 标签，发布说明采用 RELEASE_NOTES.md，当前建议勾选 Pre-release。
- [ ] Release 附件上传构建后的 JAR、源码 ZIP 和 SHA256SUMS.txt，而非整个发布资料总包。

## 实机验收（当前均未由本资料包证明）

- [ ] 纯净 Halo >= 2.27.0 安装原版评论 Next 1.0.13，评论/回复可用。
- [ ] 扩展安装、启用、停用、重启 Halo、恢复原服务正常。
- [ ] 新配置区县默认关闭，四直辖市关闭时无区县。
- [ ] 旧配置升级保留，用户能手动切换区县。
- [ ] 评论列表、回复、新评论提交、匿名及登录用户测试。
- [ ] 默认接口、自定义接口、IPv4/IPv6、超时与失败回退测试。
- [ ] 备用翻译关闭/启用、服务失败、缓存和密钥过滤检查。
- [ ] 后台作者、图标、设置保存、主页及 Issue 入口检查。

## Halo 应用市场

- [ ] 使用自己的 Halo 官网账号申请开发者身份。
- [ ] 根据 store/资料草稿填写名称、简介、README、图标、截图、版本及兼容范围。
- [ ] 确认应用市场接受 v1.0.13-4 对应的预发布格式及当前状态。
- [ ] 填写平台实际分配的 app-id，未取得前不要编造。
- [ ] 如添加 required-apps，使用前置应用真实市场 ID；不替代 pluginDependencies。
- [ ] 完成实机验收；说明私有字段接入方式、严格前置版本及维护者地域提醒。
- [ ] 按审核反馈处理。准备资料不代表审核会通过。
